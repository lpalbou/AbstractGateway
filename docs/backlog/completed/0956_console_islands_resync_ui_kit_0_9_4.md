## Summary

The console vendored the kit islands at ui-kit 0.9.1 (`kit_sources_sha256` `feed5196...`) while the
released kit is ui-kit 0.9.4 (AbstractUIC 0.8.2). The console therefore still listed each Qwen3-TTS
voice twice in the voice picker. Re-vendored from the released source; no console code changes.

## What changed

- `console_islands.py` regenerated by `python -m abstractgateway.console_islands_sync` with
  `ABSTRACTUIC_SRC` set to a `git archive` of the AbstractUIC tag `v0.8.2` (`23a31fe3`; ui-kit
  `package.json` 0.9.4, panel-chat 0.6.2), whose bundle was built there with
  `npm ci && npm run build:islands -w @abstractframework/ui-kit` (`check_islands.mjs`: OK, 429472 bytes,
  21 themes, kit 0.9.4). Provenance: `kit_sources_sha256` `f78e4ba0...`, `bundle_sha256` `b49915d5...`,
  `css_sha256` `53a904ae...`.
- `console_themes.py` regenerated by `python -m abstractgateway.console_theme_sync` from the same
  tag: only `theme_css_sha256` changes (the kit's `theme.css` gained component rules; the 21 per-theme
  blocks and `THEME_SPECS` are unchanged).

- `run_after.py` (added to this release on the lead's request, found by the Flow worker on the
  operator's email-triage flow): `quiet_reason` is `empty title` only when `notify` is an object with
  a blank title; a null or absent `notify` (an unwired On Flow End pin writes `notify: null`) is
  `no notify`. `docs/api.md` says so.

## Evidence

- `tests/test_run_after.py::test_a_null_notify_is_no_notify_not_an_empty_title` (null / "" notify ->
  `no notify`; blank-title / title-less object -> `empty title`): 7 passed; RED (1 failed) with the
  previous `run_after.py`.

- The tag is the published kit: the npm tarballs `@abstractframework/ui-kit@0.9.4` and
  `@abstractframework/panel-chat@0.6.2` carry `src/theme.css` and `src/panel_chat.css` byte-identical
  to the tag's (the islands bundle itself is not in the npm tarball, see abstractuic
  `docs/console-islands.md`, so it is built from the tag). abstractuic `main` equals `v0.8.2` for
  `ui-kit/{src,islands,scripts}` and `panel-chat/src`.
- Drift pins against the released kit: `tests/test_gateway_console_islands_sync.py` and
  `tests/test_gateway_console_theme_sync.py` 8 passed (with the built bundle: byte-for-byte module
  regeneration). Mutation check: the previous `console_islands.py` (0.9.1) fails
  `test_vendored_islands_match_the_kit_sources` against the same kit; the previous `console_themes.py`
  failed `test_generated_module_matches_the_kit_source_exactly`.
- Full suite: see the 0.17.1 PR.

## Findings left open

- AbstractObserver's `after_the_run.tsx` renders `no notify` as "Nothing to notify: this flow has no
  Notify me step." A flow that has a Notify me step the run did not reach reads wrong; "this run did
  not reach a Notify me step" would hold in both cases (AbstractObserver follow-up).

- The bundle now carries the kit's Create-a-voice / Manage-voices styling, the panel-chat tool approval
  card and the shared duration format, but the console renders none of them: its voice pickers
  (`console.py` default-voice and entity pickers) pass no `creation` / `voiceLibrary`, the Sandbox chat
  island gets no `interaction` and its messages carry no `toolActivity` / `metrics`, and the console
  formats its own chip (`formatSandboxDuration`, "205.8s" style). Adopting them is console work
  (found by the adversarial review of this release).
- `tests/kit_release.py` looks for the tag `v<ui-kit version>` (`v0.9.4`) while AbstractUIC tags its
  root version (`v0.8.2`), so without `ABSTRACTUIC_SRC` the drift pins read the checkout as-is, not the
  tag (pre-existing).
