# 0974 — The console re-syncs its vendored kit to ui-kit 0.9.6

**Status**: planned · **Priority**: P1 · **Created**: 2026-10-29
**Cross-package**: AbstractUIC 0.8.5 (ui-kit 0.9.6, panel-chat 0.6.5; on npm 2026-10-29).
> Root link: AbstractFramework release-closing wave 2026-10-29 (the lead's order, via the merge desk).

## Why
The console carries a generated copy of the kit (`src/abstractgateway/console_islands.py`, `ISLANDS_PROVENANCE.kit_version`
= "0.9.4"; regenerated by `console_islands_sync.py`, pinned by `tests/test_gateway_console_islands_sync.py` against the
sibling kit checkout). The copy is behind the kit, so everything the kit changed since then is missing from the console:
- tool calls in words on approval cards (kit 0068, panel-chat 0069);
- one account widget;
- the voice-change rule;
- the reference length;
- the failed read-aloud reason.

The operator sees the old rendering on the gateway console (8443, 8080) while the other clients get the new one.

## Scope
- Regenerate the islands bundle and CSS from ui-kit 0.9.6 / panel-chat 0.6.5:
  `(cd abstractuic/ui-kit && node scripts/build_islands.mjs)`, then `python -m abstractgateway.console_islands_sync`.
  Update the provenance pin.
- Make the pin visible in CI. The sync test reads the sibling checkout, which CI may not have, so CI also checks the
  copy's `kit_version` against the kit floor the console declares. A stale copy then fails CI even without the sibling.
- Re-check the console surfaces that mount kit islands (top bar, appearance dialog, sandbox chat) and any approval
  card the console renders.

## Done when
The console's vendored copy says `kit_version: "0.9.6"`, the sync test is green, and on the operator's instance (8443 or
8080, at a stated sha) a tool approval in the console reads in words ("Fetch the page …"), with no JSON on the card.
Until then: "in a PR, not done".
