### Fixed
- "Update llama.cpp" on a Linux NVIDIA server now installs the CUDA wheel (the engine installer detects the GPU with `nvidia-smi -L`, as the root installer does).
- "Update llama.cpp" never leaves the engine broken. The new wheel is downloaded into a staging folder and loaded there first (version, GPU offload, `libggml-cuda` on a CUDA build). Only a wheel that passes replaces the installed one, and it replaces llama.cpp alone (`--no-deps`). If the installed copy then fails the same check, the previous version is put back. An update never builds from source and never asks for a compiler. A refused or failed update keeps the card Ready and shows why in one sentence (before: "Needs a prerequisite ... a C/C++ compiler" over a working engine).
- A first CUDA llama.cpp install that carries no `libggml-cuda` or reports no GPU offload fails the job with a readable sentence (before, it was only a warning in the log).
- Engine install texts say "for this computer": the gateway's service account serves every user ("for this account" is gone from the Ollama notes, the location choice and the administrator reasons).
